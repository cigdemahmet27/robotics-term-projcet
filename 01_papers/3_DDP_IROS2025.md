# Paper 3 – Decremental Dynamics Planning, DDP (IROS 2025)

> Y. Lu, T. Xu, L. Wang, N. Hawes, X. Xiao, "Decremental Dynamics Planning for Robot Navigation," *IROS 2025*, pp. 4559–4565. doi:10.1109/IROS60139.2025.11246580
> George Mason University (RobotiXX lab, Xuesu Xiao, the organizer of the BARN challenge) + Oxford. Code: github.com/yuanjielu-64/barn_challenge_lu (ROS 1). **2nd place, BARN Challenge 2025** (simulation and real phases).

## 1. The problem in plain words

Robot navigation is usually split in two:
- **Global planner:** plans the whole route to the goal, but treats the robot as a **point that can move in any direction** (no dynamics) to stay fast.
- **Local planner:** follows the route for the next ~1–2 s using the **real robot dynamics** (it can't turn instantly, has max speeds and accelerations).

**The gap:** the global planner can choose a route that the real robot **physically can't follow** (a narrow zig-zag passage). The local planner then gets stuck or collides. The split is "all dynamics" vs "no dynamics", with a hard cut at a time or distance threshold.

**DDP's idea:** don't cut, **fade**. Use high-fidelity dynamics for the near future, and gradually coarser dynamics further out.

## 2. Background you need

| Concept | Simple explanation |
|---|---|
| **Dynamics / kinodynamic constraints** | Rules of how the robot can move: max speed, acceleration, turning radius. A differential-drive robot (like a Jackal) can't move sideways |
| **Differential drive** | Two independently driven wheel sides; control = linear velocity v + angular velocity ω |
| **Holonomic point mass** | Imaginary robot that is a dot and can move in any direction instantly |
| **Trajectory rollout / forward simulation** | Apply a candidate control sequence to the dynamics model and "simulate" where the robot will go |
| **Integration interval Δt** | Time step of that simulation. Small Δt = accurate but expensive |
| **DWA (Dynamic Window Approach)** [Fox '97] | Sample (v, ω) pairs reachable in the next instant, roll each one out, score the trajectories (goal progress, obstacle distance, smoothness), pick the best |
| **MPPI (Model Predictive Path Integral)** [Williams '16] | Sample thousands of noisy control *sequences*, roll out, weight each by exp(−cost), average. Nav2 has an MPPI controller |
| **Log-MPPI** | MPPI variant with log-normal sampling noise |
| **BARN dataset** [Perille '20] | 300 simulated Gazebo worlds of obstacles generated by **cellular automata** (random grid evolving into cluttered maps), ranging from easy to very hard. The robot drives from start to goal |
| **BARN challenge** | Yearly ICRA competition on BARN worlds (+50 secret test worlds), with a Jackal |
| **BARN score** | s = 1_success × OT / clip(AT, 2·OT, 8·OT), where OT = optimal time and AT = actual time. Rewards success and speed |

## 3. Method, step by step

### 3.1 Formalization (Sec. III)
- Dynamics: s_{t+1} = f(s_t, u_t; θ) (Eq. 1), where θ = model parameters (fidelity, Δt, …).
- Conventional split (Eq. 2): θ = full for t ≤ τ (local), θ = ∅ (no dynamics) beyond (global).
- **DDP generalization (Eq. 3):** θ_t changes **with time along the rollout**. The conventional split is a special case.

### 3.2 Implementation (Sec. IV)
Two "fidelity knobs" that decrease along the rollout:
1. **Integration interval grows** (Eq. 4): Δt_t = T·[((t+1)/T)^p − (t/T)^p], with small steps first and big steps later. p controls the growth rate.
2. **Fewer collision-check points** (Eq. 5): N_t = n·(1 − t/T)^p. Near the robot, check many points on its outline; far away, check fewer.

They plug DDP into **DWA, MPPI, Log-MPPI**, plus a **standalone DDP navigation system** with modes: high speed → low speed → brake → **recovery (rotate / reverse)**, switched by velocity thresholds (Fig. 3).

## 4. Experiments & results

- 300 BARN worlds × 3 runs, max speed **1.0 / 1.5 / 2.0 m/s** (Table I). Metrics: success %, collision %, timeout %, avg time, BARN score.
- **Every planner improves with DDP**, e.g. MPPI at 2.0 m/s: success 71.0% → 79.3%; Log-MPPI at 2.0 m/s: 20.9% → 40.5%.
- **Note:** success **drops sharply with speed** (DWA: 90.8% → 62.7% from 1.0 to 2.0 m/s). Failures are mostly **collisions**. Useful for us (see below).
- The 25 hardest worlds (Table II): the standalone DDP reaches 45.7% success, still low, so the hardest worlds remain unsolved.
- BARN 2025 leaderboard (Table III): DDP 99.0% success, 2nd place.
- Real world: 2 clutter courses, DDP 10/10 success vs ≤ 2/10 for the others.
- Sensitivity (Table V): the exponent p barely matters.

## 5. Strengths

- ✅ Simple, general idea that improves 3 different planners
- ✅ Large, standard benchmark (300 worlds × 3 speeds × 3 runs) with clear metrics
- ✅ Strong competition result, code available

## 6. Limitations (critical analysis)

| # | Limitation |
|---|---|
| 1 | **Not a failure-detection method.** It reduces failures but cannot *predict* them; recovery is a crude velocity-threshold state machine |
| 2 | Planners are evaluated **"without any backup planners and recovery behaviors"**, so how DDP interacts with recovery is unknown |
| 3 | The fidelity schedule is hand-designed (p); future work suggests "adaptive fidelity reduction" |
| 4 | Static obstacles; lidar-only local representation |
| 5 | Even with DDP, the hardest worlds fail ≥ 50% of the time, so **failure handling is still needed** |
| 6 | 2025 paper, so fewer citations so far (weaker as a *primary* paper) |
